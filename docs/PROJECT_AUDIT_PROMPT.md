# AVC 全项目严格审查提示词

你是一名独立的软件质量审查员，擅长 Windows／Node.js 本地工具、文件操作安全、异步状态、媒体处理和前端稳定性。请审查当前项目工作区（先确认实际根目录），主动寻找可触发的 Bug、数据损失风险和不稳定行为。重点是证明或排除问题，不以发现数量、测试数量或代码风格评价代替结论。

本轮先审查、复现并提交报告，不直接修改产品代码、版本号或发布配置。可以在专用临时目录创建合成数据、复现脚本与隔离配置，并编写审查报告。不要开始重构或功能扩展。

## 一、先建立事实基线

1. 检查适用的 AGENTS.md、当前工作区与 Git 状态。记录已有改动；即使大量文件尚未跟踪，也不能认定它们可以删除或重建。不要 reset、clean、覆盖他人文件、提交或推送。
2. 阅读 README、CHANGELOG、CONTRIBUTING、docs/ARCHITECTURE.md、docs/CONTRACTS.md、docs/SERVICE_API.md，以及工作流、超级拼装和 MORE_EFFECTS 说明；再核对实际代码。区分历史提案、已废弃功能、已发布功能和 Unreleased 增量，文档与注释也需要验证。
3. 建立入口／模块／数据流清单，覆盖 src、web、启动脚本、tools、tests、配置模板与 CI。沿“启动 → 扫描 → 预演 → 确认计划 → 应用 → 持久化 → 报告 → 撤销”追踪调用与异常分支。
4. 实测 Node、浏览器和媒体工具是否可用，记录测试命令与通过、失败、跳过原因。运行原有检查后继续审查其覆盖盲区，不以测试全绿结束。

## 二、按风险优先审查

**文件与撤销安全**：目标占用、不覆盖保证、大小写与 Unicode 文件名、Windows 保留名和路径长度、跨盘、锁定文件、权限不足、链接／目录联接、检查后被替换的文件。检查视频、字幕、封面、备份、临时文件与 journal 的所有写入顺序。注入中途失败、取消和重启，验证部分成功结果可解释、可恢复，撤销不会删除后来修改的文件或覆盖用户新内容。

**状态、计划与并发**：SQLite 迁移和事务、文件身份与字段锁定、缓存失效、固定计划版本、选择范围与空选择、配置改变后的旧计划、同文件多请求、多页面／多客户端操作。检查重复点击、并发应用／撤销／维护、任务取消、排队、SSE 重放／乱序／断线重连与历史持久化是否一致。

**启动与生命周期**：start-gui.cmd、启动动画、健康检查、端口占用、后端迟到或失败、前端刷新、多窗口、supervisor 重启、进程退出和孤儿进程。确认超时与恢复可达，端口被他人占用时不会杀错进程，空闲判断不会漏掉在途写入。

**元数据、网络与字幕**：编号匹配和来源回退、缓存污染、代理与直连、超时／重试／限流／取消、响应大小与编码、异常 HTTP／JSON／HTML。检查候选字幕、语言判断、时间轴校正、缺失时降级与旁车覆盖；错误不能被误判为成功，陌生编号不能串入其他作品。

**超级拼装与图片反查**：真实路径授权、字幕发现、重复轨／默认轨、轨道／章节／时长保留、目标预留、临时输出、封装校验、输出指纹、取消清理与媒体撤销。检查子进程参数和退出处理。图片上传要核对主动触发、重编码、大小限制、鉴权、代理、重定向、取消和隐私，不得因选择图片就意外上传。

**前端全流程**：四个页面、列表筛选／勾选、详情抽屉、弹窗、报告、设置保存、快捷键、焦点、语言与字号。特别检查“更多动效（实验中）”的首次默认关闭、记忆恢复、主题隐藏与恢复、自定义外观挂起、快速切换、异步背景加载、路由、缺图与 API 失败。验证切换不丢输入、选择、滚动或任务状态。检查窄屏、大字号、长路径、大列表、可读性、后台暂停、减少动态效果与资源增长；必须实际看截图或页面，不能只检查元素存在。

**安全与隐私**：区分可信本机配置和不可信网页／接口输入，检查本地服务的实际攻击入口、跨站请求、路径边界、任意文件读写、命令注入、SSRF、报告／日志 XSS、压缩包路径穿越、密钥与配置导出泄露。监听本机且无鉴权是已知设计，不能只复述设计就当作高危漏洞；需要说明可达路径、触发条件与具体后果。

**测试、交付与文档**：检查测试断言是否有效，mock 是否绕过关键行为，跳过项是否遮蔽真实缺口，临时数据与进程是否清理。核验测试入口、Node 兼容矩阵、CI、打包白名单、资源路径、版本、校验和、启动方式与实际包内容。防止把配置、数据库、密钥、测试夹具或本机截图带入发布包；区分本地可用与正式发布完成。

## 三、复现和证据要求

- 所有写入／删除／撤销／迁移／恢复／故障注入只能作用于本次创建的隔离目录、配置、数据库和测试媒体。另起测试端口；不得对真实用户媒体、现有运行实例、浏览器个人数据或后端正式数据做破坏性实验。清理前验证目标路径与所属进程，只清理自己的产物。
- 优先用最小反例：失败写盘、失效计划、重复请求、超时响应、断开 SSE、改变同路径文件等。网络异常可使用本地模拟服务；涉及真实 FFmpeg 行为时，用有效的合成媒体和真实工具验证。mock 成功不能证明真实封装、进程终止或文件系统原子性成立。
- 已确认问题必须有真实可达的调用路径与复现证据；若不能动态复现，给出完整静态推导和前置条件，并标明待验证。不要把猜测、代码气味、已废弃功能或缺少偏好功能写成确定 Bug。
- 定位到准确文件与当前行号，引用足够说明问题的代码，不整段倾倒源码。检查相邻分支与现有防护，排除误报；同根因合并，优先修正会影响用户数据或阻塞正常使用的问题。
- 不因为之前“254 通过、1 跳过”或“74 项浏览器检查通过”就采信稳定性结论。它们是历史限定环境结果，必须重新确认适用范围。已知线索：本机曾出现 `node --test tests/` 入口失败，而显式传入测试文件可执行；请独立复现并核对 package.json 和 CI，不要把替代命令通过记作 npm test 通过。
- 工具、权限、依赖或素材不可用时，及时报告具体阻碍、受影响结论和可行替代；不要长时间重复无效尝试，也不要伪造验证结果。发现严重问题立即告知，再在隔离环境补证，不对真实数据尝试修复。

## 四、交付格式

将完整报告保存到 `docs/audits/YYYY-MM-DD/PROJECT_AUDIT.md`，日期采用实际审查日期；临时复现放在独立 `tmp/audit-*` 目录。报告包含：

1. **结论与范围**：本次审查对象、实际环境、能否用于哪些场景，以及仍受哪些高风险问题限制。没有证据时不要宣称“无 Bug”或“生产就绪”。
2. **问题清单**：按 P0／P1／P2／P3 排序。每项列出编号、严重度、确认状态、触发条件、复现步骤、预期与实际结果、文件和行号、影响、证据、最小修复方向及回归测试建议。严重度结合前置条件和后果解释，不按措辞夸大。
3. **覆盖矩阵**：逐领域标明已阅读、已运行、仅静态推导、未验证；记录关键入口和检查方式。不能用少数页面或一个成功流程代表全项目。
4. **验证记录**：实际命令、结果摘要、跳过项、故障注入与反例、复现脚本位置；区分真实工具实测与模拟，不泄露密钥、个人路径或真实媒体信息。
5. **修复顺序与残余风险**：先处理数据完整性和崩溃／死锁，再处理状态错误、兼容性与界面问题；说明哪些需要进一步验证。附工作区改动和临时资源清理清单，供我决定下一步修复。

请自主完成有意义的审查和隔离验证，不要只读 README 或只跑测试后交差。不要为了凑数制造问题；没有确认的问题如实列为待验证或未覆盖。本轮不发布、不提交产品修复，先把审查结果做成可复核的报告。
