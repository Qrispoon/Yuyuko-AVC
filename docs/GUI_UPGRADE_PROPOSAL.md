# GUI 工作流升级提案

日期：2026-11-09  
依据：当前 v0.7.4 工作区源码、ROADMAP、接口及数据契约  
状态：原七项曾获批准并实现；2026-11-09 根据实际使用反馈撤回 U2 待处理中心、U6 新增队列面板及专用后端能力。本文保留原提案以供追溯，不代表当前功能列表；当前交付见 docs/V075_WORKFLOWS.md。

## 1. 范围与取舍

- **目录配置档：废案**。不建设按目录保存、自动切换、继承业务设置的配置系统。
- 本次评审七项：只补缺项、待处理问题中心、字段级修正与锁定、字幕候选对比、冲突解决器、任务队列面板、可读的历史报告。
- 队列任务可以携带本次明确选择的目录、文件与执行选项；这是一次任务的快照，不是目录配置档。
- 本方案不扩展递归扫描、目录监视、NFO、跨目录归档等旧路线图内容。这些与本次范围无依赖，不顺带实施。
- 沿用粉樱风格、深浅主题、字号调节与中英文界面，继续保持零第三方运行依赖。

## 2. 当前基础与真实差距

| 项目 | 当前可复用能力 | 本次需要新增的能力 |
|---|---|---|
| 只补缺项 | 整文件跳过判断、合格同名 SRT 复用 | 每个字段、每个产物独立检查与执行；跳过原因可见 |
| 问题中心 | 失败 / 无字幕 / 未确认等筛选、单文件重跑 | 同一文件多个问题、处理建议、跨页面处理状态 |
| 字段修正 | 手动番号、单文件预演、元数据展示 | 标题 / 演员 / 日期 / 厂牌等编辑、来源与锁定、持久化 |
| 字幕对比 | 列候选、下载指定候选、已安装字幕前 30 条预览 | 安装前分析候选、双栏对照、可解释的推荐与手动选择 |
| 冲突解决 | 同批目标提示、同大小目标跳过、占名时自动编号 | 用户可选择策略、整批占位与重新校验、明确最终名称 |
| 队列面板 | 后端 FIFO、queued/running、取消、单任务 SSE | 队列可视化、插入任务、排序、暂停调度、持久恢复 |
| 历史报告 | 任务历史、摘要、原始日志、JSON 导出、撤销 | 可读的实际动作清单、前后对照、失败原因、HTML 导出 |

代码入口：`src/pipeline.mjs`、`src/core/state.mjs`、`src/core/rename.mjs`、`src/subs/manual.mjs`、`src/server.mjs`、`web/app.js`。

现状中需要特别处理的约束：

1. 处理管线目前把元数据获取、改名、字幕与封面串在单个文件流程里，不能只靠前端过滤实现可靠的“只补缺项”。
2. 队列中的任务目前在开始时读取全局配置；待执行任务并非完整持久化队列，重启读取到非终态历史时会标为中断。
3. 字幕候选列表只包含来源、名称、语言和地址等基本信息；详细时间轴与评分需要实际下载字幕后计算。
4. 同大小文件只能判断为疑似重复，不能证明视频内容相同。
5. 部分字幕 / 封面写入只有在存在改名 journal 条目时才能附加记录；新增“只补产物”必须补齐独立写入的撤销链路。

## 3. 共用底层：操作计划、人工修正与执行记录

七个功能共用一套可校验的操作计划，避免界面预演、排队等待与实际执行出现不同结果。

### 3.1 计划结构

建议新增计划服务，按文件生成：

- 稳定文件记录 ID、当前路径与 stat 校验信息；文件大小 / 修改时间用于检测变化，不作为跨文件身份合并依据。
- 有效元数据、字段来源、人工修订版本与锁定状态。
- 动作数组，如补标题、安装字幕、下载封面、改名；每项带目标、原因、保留 / 待执行 / 阻塞状态。
- 业务配置快照或其不可变引用、执行模式、所选文件、冲突策略、字幕选择。
- 计划版本与有效性校验；应用前核验文件、人工修订与目标占用情况。

**任务按用户确认的计划执行**。元数据来源发生变化时，不能在应用阶段悄悄生成另一套名字；需要刷新计划。排队期间路径、文件、修正或目标冲突变化时，任务转“需要复核”。

计划不是媒体写盘：可以保存应用内部状态与必要缓存，媒体目录的改名、字幕、封面写入继续在“应用”后执行。

### 3.2 人工修正独立保存

建议在 SQLite 新增人工修正 / 字段偏好记录，与来源站点的 code 缓存分开：

- `原始来源值 → 人工修正 → 锁定规则 → 有效值`，不把某个文件的个人修改污染到所有同番号文件。
- 程序内改名更新路径映射，人工修正跟随同一文件记录；撤销改名时映射还原。
- 外部移动后无法确认身份时提示重新关联；不凭同番号或同大小自动继承修正。
- 人工修订改变后，旧预演计划失效。解锁允许后续刷新更新，恢复来源值另设明确操作。
- 保存人工修正不直接改媒体文件；保留修订记录。撤销媒体操作默认保留人工修正，可另行恢复上一版修正。

### 3.3 实际动作与撤销

执行结果按动作记录“计划 / 成功 / 保留 / 跳过 / 失败”，供问题中心和历史报告共用。

只下载字幕、只下载封面而没有发生改名，也必须有可撤销记录。新 journal 若扩展版本，读取器保留旧版兼容并新增往返测试；旧报告缺少细节时显示“未记录”，不推断已经执行的动作。

## 4. 七项升级设计

### U1. 只补缺项

**入口与界面**：工作台“本轮选项”增加执行模式：完整整理 / 只补缺项；缺项模式下可选元数据、主字幕、附加语言字幕、封面。列表显示“缺标题 / 缺字幕 / 缺封面 / 已齐全”，预演卡展示保留多少项、补多少项。

**建议规则**：

- 元数据：只填空值；已有人工值和锁定值优先。缺项模式不能被“强制重跑”隐式改成覆盖模式。
- 字幕：文件存在且基本解析有效，并符合所选语言才算可用；损坏、语言不符、时长未知分别标示，未知不直接判错。
- 封面：检查实际文件及图片格式特征，避免仅凭数据库路径判断已存在；不因远端换图自动替换本地封面。
- 默认保留视频文件名；补到的元数据先存入应用。用户可另外勾选“根据补全结果重新生成文件名”，进入预演与冲突检查。
- 第一版不在缺项模式自动嵌入封面；嵌入视频的现有状态不能仅凭旁车图片推定。

**实现**：拆分管线检查与执行阶段，按缺项生成动作；整文件“已完成”标志不再阻止真正缺失的字幕或封面补齐。覆盖行为由独立、明确的选择触发。

**验收**：同一文件已有有效字幕但缺封面，只下载封面；再运行无重复写入；只补封面后能够撤销；手工标题始终保留。

**复杂度：高**，依赖共用操作计划与独立产物撤销。

### U2. 待处理问题中心

**入口与界面**：顶部新增“待处理”及数量徽标，沿用现有卡片；分类为编号、元数据、字幕、封面、命名冲突、执行失败。显示“受影响文件数”和“问题条数”，避免一个文件的多个问题被混成单一状态。

**每条信息**：文件、问题、具体原因、最后检查时间、建议动作。可直接补番号、编辑字段、比较字幕、处理冲突、重试选中项。

**实现**：从扫描状态、操作计划与执行结果生成稳定问题代码；单独保存忽略偏好。优先支持当前目录，另可查看应用已记录目录；不主动扫描用户未选择的磁盘目录。

- 修复后重新验证，再移出待处理；不能仅点击“完成”就改变真实状态。
- 支持“忽略此问题 / 恢复提醒”；关键文件状态变化后新问题重新出现。
- 网络故障等共因给出汇总提示，同时保留受影响文件列表；批量重试只处理选中问题对应动作。
- 扫描尚未取得元数据时标“待检查”，不把所有未预演文件直接算作元数据损坏。

**验收**：同一文件同时缺字幕、封面时显示两项问题；补好封面后只剩字幕问题；忽略可撤销；问题计数与实际文件一致。

**复杂度：中**，基础规则可先做，动作入口随其他升级逐步接入。

### U3. 字段级修正与锁定

**入口与界面**：详情抽屉增加“编辑资料”。提供标题（日文 / 中文）、演员、发行日期、厂牌、封面地址与作品编号编辑；字段旁显示来源、原值、锁图标及“恢复来源值”。

**建议规则**：

- 修改并保存的字段默认锁定；锁定字段在重新抓取和只补缺项时都不会被覆盖。
- 演员采用标签输入，日期校验格式，封面链接校验协议，文件名由有效字段生成并显示即时预览。
- 手动清空并锁定代表“刻意留空”；与尚未获取到的空值区分，避免反复自动填回。
- 片长第一版显示来源与实测值，采用只读，避免人工误填影响字幕校正。
- 作品编号变更意味着身份可能改变：使旧元数据、候选字幕、封面关联与计划失效，并提示确认哪些人工锁定字段要保留。

**实现**：增加独立修正记录、字段来源与修订版本；原始来源值保留在缓存，有效值由统一合并器计算；所有命名、补全、报告都读取有效值。

**验收**：锁定中文标题后重抓仍保留；解锁后允许更新；改名、刷新和重启不丢锁定；同番号另一文件不被误改。

**复杂度：高**，是后续缺项判断与冲突策略的基础。

### U4. 字幕候选对比

**入口与界面**：现有候选列表增加复选框和“对比”，桌面并排展示两份，窄屏切换 A / B。来源、语言、条数、大小、首末时间、时间覆盖与警告置顶，下方按相同时间窗口对照字幕。

**实现**：

- 复用现有候选查询与 SRT 解码 / 校验能力，新增安装前分析接口。
- 用户选择候选后才下载分析，缓存到应用临时区；比较期间不写到视频旁、不触发自动安装。
- 把解析、语言、时长贴合与时间轴异常等事实分开呈现。评分附推荐原因，不宣称已经识别翻译质量或音画同步。
- 支持查看原始时间轴与校正后预览，显示缩放 / 平移参数；片长未知时不输出误导性的匹配分。
- 选定结果存入操作计划，显示目标字幕路径、备份与覆盖动作；已有“立即安装”作为独立明确操作保留。
- 设置下载上限、超时、缓存期限；其中一个源失败不妨碍查看另一个候选。过期选择在执行前重新校验。

**验收**：两份候选可在安装前对比；其中一个不可下载时仍可查看另一份；选定候选安装与报告一致；对比关闭后媒体目录没有新增文件。

**复杂度：中高**。

### U5. 冲突解决器

**入口与界面**：预演汇总卡的“冲突 N 项”进入专用面板，按相同目标路径分组，展示原文件、已有目标、大小、拟定名称与策略。

**第一版策略**：跳过本项 / 自动追加序号并显示最终名 / 自定义名称 / 纠正番号后重新预演。支持“同类冲突批量使用策略”。

**实现**：

- 全批次统一计算目标占位，覆盖 Windows 大小写不敏感、非法字符、保留名、末尾空格与句点、路径长度、视频与旁车占名情况。
- 将选择和最终目标名写入计划；运行前重新检查，执行过程中协调目标占位，避免多个工作线程领取同一个名称。
- 目标占用发生变化时转“需要复核”，不静默换成另一个名字。
- 同大小目标标“疑似重复”，用户可跳过或保留两份，不自动删除。第一版不提供覆盖视频、自动合并或交换循环改名。

**验收**：两条记录指向同一目标时，预演就能分配无冲突名称；执行与预演一致；执行前新增占名文件会阻止相关动作而非覆盖。

**复杂度：高**，需要后端目标协调，不能只做前端改名框。

### U6. 任务队列面板

**入口与界面**：顶部任务按钮带“运行 1 / 等待 N”徽标，打开侧面板；运行项显示进度，等待项显示顺序、目录、动作类型、文件数和创建时间。

**操作**：运行中可另选目录创建预演任务并“加入队列”；等待项支持上移 / 下移、置顶、取消、查看计划。提供“暂停队列 / 继续队列”。应用任务必须来自已经确认的有效计划。

**实现**：

- 复用当前串行任务调度，保留文件级并发 1–4；新增队列级接口和状态推送，不将多个写盘任务并行化。
- 编辑工作台和运行任务状态分离，切换目录准备下一项时不覆盖当前任务展示与 SSE 订阅。
- 任务保存所选文件、配置和人工修订快照；执行前校验，不能因用户后来改了全局配置而悄悄改变等待任务。
- “暂停队列”仅停止领取下一个任务，当前任务继续；“停止当前任务”沿用完成在途文件后取消的语义，界面明确区别。
- 创建、排序、取消和状态转移均持久化，重启后等待项恢复为暂停待复核；中断的运行任务标识部分执行，不自动续写媒体目录。
- 重启恢复、计划过期或跨任务占名时重新检查；只对用户已确认且仍有效的应用计划执行写盘。

**验收**：三个目录任务顺序可见可调整；暂停后不启动下一项；重启能看到等待项与中断项；改全局模板不改变已确认任务快照。

**复杂度：高**，建议最后接入，复用前面已经稳定的计划服务。

### U7. 可读的历史报告

**入口与界面**：历史任务增加“查看报告”，保留 JSON 导出与原始日志。报告页包含任务摘要、前后文件名、每项产物、失败 / 跳过原因、当前问题及撤销入口。

**实现**：

- 第一批就可以用现有 report / journal 渲染可读页面：实际有记录的显示，无记录的显示“未记录”，绝不把预演路径当成已写入路径。
- 随操作记录完善，按文件展示改了什么、保留了什么、人工锁定了什么、使用了哪份字幕，以及备份 / 撤销状态。
- 区分“预演报告”和“应用报告”；区分任务结束与文件每个动作成功，支持只看失败、仅写入项、仅保留项等过滤。
- 提供单文件 HTML 导出，无远程图片 / 脚本依赖，可离线阅读、浏览器打印；JSON 继续保留用于排障。
- 报告固定本次历史事实；重新扫描得到的当前状态另设区域和时间标记，不回写历史事实。导出时转义文件名与所有外部文本。
- 撤销资格根据当前后端状态判断；只读导出不带执行操作。

**验收**：打开旧报告能看懂已有信息；新报告精确区分仅补字幕与改名；导出离线 HTML 可正常阅读；失败与撤销结果不被“成功”总数遮盖。

**复杂度：基础版中、完整动作追踪版中高**。

## 5. 推荐交付顺序

以下批次已获用户批准，均已合入 v0.7.5；保留分批结构以说明实现依赖。

| 批次 | 建议版本 | 交付内容 | 用户能获得的完整流程 |
|---|---|---|---|
| A | v0.7.5 | 共用操作计划、独立产物撤销、字段修正与锁定、只补缺项、问题中心基础、可读报告基础 | 扫描 → 找缺项 → 修正锁定 → 只补缺项 → 看报告与撤销 |
| B | v0.7.5 | 字幕候选对比、冲突解决器、问题中心动作补齐、报告动作追踪完善 | 问题中心 → 比字幕 / 解冲突 → 明确计划 → 应用 → 追溯 |
| C | v0.7.5 | 队列面板、快照隔离、排序 / 暂停 / 恢复及重启复核 | 多任务准备 → 排队 → 自动调度有效计划 → 汇总处理结果 |

问题中心与报告优先搭出页面，但完整判定和动作入口跟随对应业务能力交付，避免为临时数据形态重复开发。

## 6. 实施质量与评审选择

每批均包括：中英文字条、字体与窄屏适配、接口与数据契约增量、README / CHANGELOG、离线集成测试、浏览器实测。

重点验收矩阵：

- 预演不写媒体目录；只有明确应用才产生媒体变更。
- 只补字幕 / 封面可以单独撤销，原文件备份可还原。
- 人工锁定、保存后刷新、程序改名与重启仍一致。
- 同批冲突、排队后占名、配置 / 文件变化都能使相关计划失效。
- 字幕候选对比下载失败、片长未知、语言不符不会误导推荐。
